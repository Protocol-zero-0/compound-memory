# 推送隐私闸

记忆系统存的是你本人的原话。最容易漏出去的时候,不是记忆本身出机,而是**你或 AI 在写代码、
写文档、举例子的时候,顺手把真实内容写进了仓库**,然后推到 GitHub。这道闸就是拦这个的。

## 三道检查

| 检查 | 查什么 | 严格档 | 发布档 |
|---|---|---|---|
| 词表 `[private]` | 别人的名字、联系方式、内部地址、各种 ID 和密钥 | ✅ | ✅ |
| 词表 `[brand]` | 你自己的品牌、产品、价格、对外名字 | ✅ | — |
| 原文指纹 | 新增内容里有没有一段 ≥11 个汉字跟你说过的话逐字相同 | ✅ | — |

- **严格档**(默认):开源代码、给别人的项目提 PR、新仓库。
- **发布档**:你自己的站点和业务仓库 —— 上面本来就会有你的品牌、价格和你写的文案,
  那些在这里不是泄露。只拦真隐私那一档。实测:对一个业务发布仓库,严格档会误拦大半推送,
  发布档只剩客户名这类值得人看一眼的命中。

词表在 `~/.compound-memory/privacy-terms.txt`,**在任何仓库外面**,因为词表本身就是隐私。
原文指纹来自你所有会话的原文、会话标题、记忆库和你在 `privacy.extra_sources` 里列的文件,
`cm privacy-index` 重建,**只存哈希**,拿到索引也还原不出你说过什么。

## 本机全局安装

```bash
bash tools/global-gate/install.sh               # 装;重复跑是安全的
bash tools/global-gate/install.sh --uninstall   # 原样摘掉
git config --global privacy-gate.owner 你的名字   # 拦截提示里写谁来拍板
```

它做的事:

1. 设 `git config --global core.hooksPath`,所以**本机每个仓库**推送前都先过闸。
2. 仓库自己原来的钩子(lefthook、husky、手写的)**照常串着跑**,不会因为全局设置而失效。
3. 自己设了 `core.hooksPath` 的仓库(仓库级或工作区级)全局设置管不到,逐个"包一层":
   记下原值、改指向闸门、闸门再转回原值。
4. 每晚巡检:重建原文指纹;把新冒出来的自带钩子目录的仓库重新包进来
   (`npm install` 时 husky 会悄悄设一个);有人改了放行开关就通知你。

只管推到 `github.com` 的推送。只查这次推送里**别人还没有的新提交**(排除任何远端已有的,
给上游项目提 PR 时不会把上游历史扫一遍)。检查本身跑不成时**当作不通过**。

## 被拦下之后

终端里会列出每一处命中和一个确认码。先改掉(历史里也要改),再推。
逐条看过、确认不是隐私,由你本人放行这一次:

```bash
PRIVACY_GATE_ACK=<确认码> git push ...
```

确认码只对**这一次的这些命中**有效。每次拦截、每次放行都记在 `~/.compound-memory/privacy-gate.log`,
配了通知就同时通知你(`~/.compound-memory/privacy-gate-notify`,收两个参数:标题、正文)。

## 每个仓库的开关(只该由你改)

```bash
git config privacy-gate.mode publish       # 设为发布档
git config privacy-gate.enforce warn       # 只报警不拦:背后有自动流程、暂时不能停的仓库
git config --add privacy-gate.allow '某人'  # 这个仓库的内容本身就是这些(比如人名库)
```

这三个开关本身就是绕过口子。巡检会记住它们的值,有变化就通知你。
如果你让 AI 替你推送,在你的全局规则里写明:**AI 不许自己放行、不许 `--no-verify`、不许改这三个开关。**

## GitHub 那一侧

github.com 上没有"收到推送之前拒绝"的办法(那是 GitHub 企业版自建服务器才有的 pre-receive)。
所以真正的闸只能在本机。GitHub 上能做的是第二道:`tools/github-action/privacy-gate.yml`,
推上去之后用同一份词表复查,兜住别的机器推的、被绕过的、网页上直接改的。
它失败时不回显命中原文(Action 日志对有读权限的人都可见),只报第几条规则、第几处。

**全自动,不用手工配**:`git config --global privacy-gate.github-owner <你的 GitHub 用户名>` 之后,
每晚巡检会:

- 给你名下**新建的自有仓库**(不含 fork、不含已归档)自动装上:先设加密词表,
  再确认 Actions 是开着的,最后推 workflow 文件。顺序反了第一次运行会失败。
- 空仓库、本机副本有改动或不同步的,这次跳过、下次再试(从远端硬推会让本机副本落后,
  它下次推送会被拒);连续 3 晚还装不上才通知你。
- 本机词表一改,把新词表同步到所有已装的仓库。

手动装单个仓库:`bash tools/global-gate/action-install.sh <owner/repo> [strict|publish]`,幂等,
只比较模板里实际生效的内容,注释改了不会产生新提交。

## 已知的边界

- 原文指纹只比中文。英文泄露靠词表。
- 只抓 ≥11 个汉字的逐字重合。改写过的句子抓不到 —— 那需要模型判断,不适合放在每次推送的路径上。
- 词表要你自己维护。新客户、新同事的名字不在词表里,就不会被词表抓到。
